## 来源和作者记录

每版的 `snapshot.json` 保存来源仓库、原始提交 SHA、源提交作者与作者时间，以及逐文件的 Git blob SHA-1、SHA-256、长度和文件模式。这里的源提交作者信息表示来源提交的归属，不表示该作者独立完成了该版本的全部代码。

这些快照通过新的非空归档提交整合，归档提交保留已确认的来源作者身份并使用本次整合时间。原始私有仓库的全部 Git 历史没有并入本仓库，原始提交 SHA 作为来源标识保留。上游快照导入时间也不自动等同于代码开发或训练时间。

归档范围为 `agent_diy`、`agent_ppo`、`conf`、`tools` 中已跟踪的 Python 源码、TOML/INI/JSON 配置，以及存在的根目录 Python 启动文件。官方指南、开发指引、设计归档、`kaiwu.json`、凭据、运行日志、缓存和模型权重不在本批范围内。

源文件字节保持不变，`.gitattributes` 对历史目录关闭换行转换。原始仓库为私有时，外部读者可能无法打开来源链接；归档源码和指纹清单仍可用于独立查看和校验。机器可读总索引见 [milestones.json](milestones.json)。

## 命名与运行方式

- 项目目录沿用根目录的完整名称：`honor_of_kings_1v1`、`honor_of_kings_3v3`。
- 版本目录统一为 `v主版本_次版本`，如 `v2_9`、`v3_5`。
- 独立说明文档使用小写下划线命名，目录入口统一使用 `README.md`，来源清单统一使用 `snapshot.json`。
- 算法包、配置文件、导入路径和模型协议采用各版本的原始约定，保证能够与来源提交对照。1v1 的候选算法主要为 `diy` → `agent_diy`；3v3 的主线为 `ppo` → `agent_ppo`，以每版说明和实际平台映射为准。
- 选择一个版本后，将其目录视为该历史项目的根目录，结合匹配的官方工程和 SDK 运行。不同版本不应同时进入一个 Python 模块导入路径。

统一准备流程见[训练与复现说明](../docs/training_and_reproduction.md)。归档未包含模型权重，历史检查点不保证兼容当前最终实现。
