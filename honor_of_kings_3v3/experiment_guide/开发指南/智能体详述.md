# 智能体详述

代码包提供 PPO 和 DIY 两套智能体实现。PPO 实现包含观测处理、动作采样、协作指令生成、样本构建和模型训练逻辑；DIY 目录用于自定义算法、特征、奖励和网络结构。

## 观测处理

智能体通过 `observation_process` 将环境返回的观测转换为模型输入。PPO 代码中，`observation_process` 会拼接三类信息：

1. 环境内置图像特征 `heroes[hero_index]["feature"]`；
2. `FeatureProcess.process_feature` 生成的全局向量特征；
3. 当前主控英雄对应的主英雄特征。

```python
feature_vec, main_camp_hero_feature_dict = self.feature_processes.process_feature(observation)
feature_vecs.append(
    np.concatenate(
        [
            heroes_info[hero_index]["feature"],
            feature_vec,
            main_camp_hero_feature_dict[heroes_info[hero_index]["config_id"]],
        ]
    )
)
```

### 特征结构

| 特征区间 | 形状 | 说明 |
| --- | --- | --- |
| `feature_img` | `[6, 17, 17]` | 环境内置图像特征。 |
| `feature_hero_frd` | `[3, 86]` | 我方英雄特征。 |
| `feature_hero_emy` | `[3, 86]` | 敌方英雄特征。 |
| `feature_soldier_frd` | `[10, 18]` | 我方小兵特征。 |
| `feature_soldier_emy` | `[10, 18]` | 敌方小兵特征。 |
| `feature_organ_frd` | `[3, 21]` | 我方机关特征。 |
| `feature_organ_emy` | `[3, 21]` | 敌方机关特征。 |
| `feature_monster` | `[20, 20]` | 野怪特征。 |
| `feature_global_info` | `[1, 47]` | 全局特征。 |
| `feature_hero_main` | `[1, 86]` | 当前主控英雄特征。 |

特征处理目录为 `agent_ppo/feature/feature_process/`。其中 `collaboration_process.py` 提供协作指令生成逻辑，`hero_process.py`、`soldier_process.py`、`monster_process.py`、`organ_process.py` 分别处理英雄、小兵、野怪和机关特征。

## 协作指令生成

`Agent.action_process` 会同时返回英雄动作和协作指令：

```python
hero_actions, coll_action = agent.action_process(observation, act_data, is_stochastic)
```

返回结构如下：

| 返回值 | 类型 | 说明 |
| --- | --- | --- |
| `hero_actions` | `dict` | key 为英雄 `config_id`，value 为该英雄的 5 维动作。 |
| `coll_action` | `list` | 4 维协作指令 `[action_type, target_runtime_id, position_x, position_z]`。 |

PPO 默认实现通过 `CollaborationProcess.build_collaboration_command` 生成协作指令：

- `reset` 时从 `observation["official_model_info"]` 缓存本局官方智能体英雄的 `runtime_id`；
- 每隔 `COMMAND_INTERVAL_FRAMES = 600` 帧发送一次协作指令；
- 当最近目标防御塔或水晶变化时立即重新发送；
- 有存活敌方防御塔或水晶时返回 `[1, target_runtime_id, 0, 0]`；
- 无可用目标或非发送帧返回 `[0, 0, 0, 0]`。

```python
coll_action = self.collaboration_process.build_collaboration_command(observation)
return hero_actions, coll_action
```

### 协作指令建议

- 先判断官方智能体英雄是否已复活、是否接近目标、当前指令是否仍有效，再决定是否发送新指令。
- 目标单位必须来自合法目标集合。目标不存在、不可选中、已死亡或不在合法集合内时，指令会被视为无效指令。
- 指令冷却期内重复发送 `SetTarget` 或 `SetPosition` 会增加无效指令数。
- 官方智能体英雄死亡不会自动清除通信状态。需要取消旧指令时，发送 `Unset`；需要切换目标时，发送新有效指令覆盖旧指令。
- 无有效指令期间，官方智能体英雄会向己方泉水移动。若希望官方智能体持续参与进攻，需要持续维护有效指令节奏。

## 动作处理

模型输出 5 个英雄动作子任务，对应 `[13, 25, 42, 42, 39]` 维：

| 子任务 | 维度 | 说明 |
| --- | --- | --- |
| `which_button` | 13 | 动作按钮。 |
| `move` | 25 | 移动方向。 |
| `offset_x` | 42 | 技能或目标点 X 偏移。 |
| `offset_z` | 42 | 技能或目标点 Z 偏移。 |
| `target` | 39 | 目标单位。 |

动作采样使用 `legal_action` 掩码。对于 `target` 维度，代码会根据 `which_button` 选择对应的 target 合法动作掩码，避免无效目标干扰训练。

## 奖励配置

奖励由环境计算，并按 reward 子项返回。可通过 `conf/train_env_conf.toml` 调整权重。

| 奖励因子 | 说明 |
| --- | --- |
| `hp_rate_sqrt_sqrt` | 血量比值开四次方。 |
| `money` | 经济增长值。 |
| `exp` | 经验增长值。 |
| `tower` | 我方防御塔和水晶血量收益。 |
| `killCnt` | 击杀。 |
| `deadCnt` | 死亡。 |
| `assistCnt` | 助攻。 |
| `total_hurt_to_hero` | 对英雄伤害。 |
| `atk_monster` | 攻击野怪。 |
| `win_crystal` | 摧毁敌方水晶。 |
| `atk_crystal` | 攻击敌方水晶。 |

### 通信策略奖励建议

可基于原始帧状态自行计算通信相关奖励，并在样本发送前修改 reward 标量。

| 奖励方向 | 说明 |
| --- | --- |
| 有效激活 | 成功让官方智能体英雄响应有效指令时给予正反馈。 |
| 协作收益 | 官方智能体在指令期间产生击杀、助攻、推塔或击杀关键野怪时给予正反馈。 |
| 无效通信惩罚 | 指令冷却中、目标非法、目标已死亡等无效指令给予负反馈。 |
| 指令切换成本 | 频繁覆盖目标或无意义切换目标时给予负反馈。 |

## 算法介绍

代码包提供 PPO 作为默认算法，同时提供 `agent_diy` 供自定义算法使用。

PPO 使用 clipped policy optimization 控制策略更新幅度，模型包含图像卷积、单位特征 MLP、共享特征融合、动作头和值函数头。训练样本使用 GAE 计算优势函数。

## 模型保存限制

- 保存模型的频率限制：2 次/分钟；
- 单个任务保存模型的次数限制：1000 次；
- 默认保存间隔由工作流控制，`GameConfig.MODEL_SAVE_INTERVAL = 1800` 秒。

## 模型评估模式

训练时调用 `agent.predict`，评估时调用 `agent.exploit`。评估阶段通常使用确定性动作 `d_action`，训练阶段通常使用采样动作 `action`。

评估任务会分别启动智能体服务，服务接口包括：

| 接口 | 调用时机 | 说明 |
| --- | --- | --- |
| `agent.reset` | 每局开始 | 重置 LSTM 状态、特征处理器和协作指令处理器。 |
| `agent.exploit` | 每个环境 step | 根据当前观测返回英雄动作和协作指令。 |

## 训练中评估

训练中评估通过 `train_env_conf.toml` 配置：

- `episode.eval_interval`：评估间隔；
- `episode.eval_opponent_type`：评估对手，可取 `selfplay`、`common_ai` 或自定义模型 ID；
- `monitor.monitor_side`：监控上报阵营。

若使用自定义模型作为对手，需要先在模型管理中获取模型 ID，并写入 `kaiwu.json`。

```json
{
  "model_pool": [12053, 12054]
}
```
